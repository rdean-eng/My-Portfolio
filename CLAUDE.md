# Claude Code — project context
Redesign my portfolio into a polished, modern, professional, and visually memorable website. Work directly in the existing project files: `index.html`, `style.css`, and `script.js`. First inspect the full project structure and existing image assets, then make the changes in place.

## Design direction

Create a clean, editorial portfolio for a Computer Science student and aspiring developer. Make it feel thoughtful, confident, and current, with strong typography, generous spacing, a clear visual hierarchy, restrained color, and high-quality use of the photos already in the `images/` folder.

Use subtle gradients, soft lighting, refined borders, and carefully chosen motion where they support the content. Avoid making the design feel like a generic template. Retire the heavy Matrix rain and glitch aesthetic if it competes with readability or the personal work. Keep effects controlled and cohesive.

## Intro and animation

Add a short, elegant first-visit intro animation that establishes the portfolio’s identity—for example, a name or monogram reveal followed by a smooth transition into the home page. Keep it brief, skippable, and never make visitors wait through it on every navigation. Make sure the site remains usable if animation or JavaScript is unavailable.

Add polished, lightweight motion throughout the site where appropriate: staggered hero reveals, smooth section transitions, gentle card and image hover effects, and scroll-triggered reveals. Use animation to guide attention rather than decorate every element. Respect `prefers-reduced-motion` and provide a low-motion experience.

## Layout and navigation

Make the portfolio responsive and comfortable to browse on phones, tablets, and desktops. Replace the current strict fixed-viewport, non-scrolling approach with a natural layout that allows content to scroll when needed. Keep navigation clear, accessible, and easy to use on small screens. Ensure active navigation state, keyboard interaction, focus indicators, and readable contrast work correctly.

Organize the content so visitors quickly understand who I am, what I’m learning, and what I’ve accomplished. Improve the page flow and section hierarchy while using the real content and assets already in the project. You may recommend a better structure for the current tabs and sections, but don’t invent projects, awards, experience, contact details, or other biographical facts.

## Privacy and content

Review the displayed personal information before redesigning. Do not prominently publish sensitive details such as my exact birth date, phone number, body measurements, or similarly private information. Keep the code’s existing source content intact where practical, but omit sensitive details from the public-facing design and tell me which details you chose to hide. Do not invent replacement facts. Preserve the family and friends section only if it can be presented tastefully and without exposing more personal information than the existing photos and captions require.

Improve copy presentation and fix obvious wording, capitalization, or consistency issues without changing the meaning of my background. Use meaningful image alt text and preserve the supplied image files and paths.

## Implementation requirements

- Keep the project lightweight and compatible with its existing static HTML/CSS/JavaScript setup. Do not add a framework or build system unless there is a clear need.
- Keep the code organized and remove obsolete styles or scripts made unnecessary by the redesign.
- Use semantic HTML and accessible controls; do not rely on inline event handlers if a clean event-listener approach fits the existing code.
- Make theme controls, photo previews, and other existing interactions work correctly if they remain in the redesign.
- Avoid unnecessary external dependencies, remote placeholder images, and effects that reduce performance.
- Ensure responsive images, sensible loading behavior, and graceful fallbacks.
- Keep the page title and site identity consistent with Robert Dean C. Kiwang.

After implementation, review the changed files and summarize the design, intro and motion behavior, responsive/accessibility choices, sensitive details omitted from the public view, and anything I should personalize. If you can preview the site in a browser, inspect it at desktop and mobile widths and fix any visible layout issues before finishing.
